\textcolor{blue}{\parab{GRACE comparison.}
GRACE is a loss-resilient neural video codec trained with randomly removed
latent coefficients so that its decoder degrades gracefully when part of the
representation is unavailable~\cite{grace_nsdi24}. We compare GRACE and
\sysname as separate systems at zero loss on one complete representative clip
from each photoreal title (FC5, FM6, and Spaceflight), reusing \sysname's saved
CRF23 run. GRACE receives the normalized source directly; frames are
edge-padded on the bottom and right to
the next multiple of 128 and cropped back after decoding. For each title, we
select the measured released GRACE rate checkpoint whose source-referenced
VMAF is nearest to that of \sysname's reconstructed output, and report
source-referenced VMAF and SSIM for both systems. GRACE size includes actual
torchac entropy payloads, BPG refresh payloads, and per-frame framing metadata.
\sysname size includes the H.264 video and measured in-band RMD; referenced
templates are assumed resident before use, so preload and runtime template
delivery contribute zero bytes. Because the released GRACE code has no
entropy-decoding path, its frames are decoded in memory from the same
quantized latent codes whose payload bytes are written. The resulting GRACE
size is therefore a measured research-container payload, not an official
interoperable wire bitstream.}

\section{Evaluation}
\label{sec:results}

We begin with the primary question: how many delivered bytes does \sysname save?
We first report net Bandwidth Savings Percentage (BSP) for every clip and for actual codec GOPs
(\S\ref{sec:res-bsp}), then separate the fixed-rate-cap result
(\S\ref{sec:res-ratecap}), template and metadata costs (\S\ref{sec:res-netbw}),
client cost (\S\ref{sec:res-client}), and component ablations
(\S\ref{sec:res-ablation}). Fixed-VBV and CRF23 results answer different
questions and are never combined into one bandwidth claim.
\textcolor{purple}{We additionally compare \sysname directly with a
loss-resilient neural codec on full representative clips
(\S\ref{sec:res-grace}).}

\parab{What produces high or negative GOP BSP?}
Across the H.264 intervals, BSP has a clear monotonic association with Rec
coverage (Spearman $\rho=0.60$), mask coverage ($\rho=0.49$), and template
reuse ($\rho=0.32$). Long GOPs
also tend to save more ($\rho=0.56$), because an expensive keyframe is
amortized across more reusable predicted frames. High-BSP GOPs therefore
combine sustained Rec operation with repeated template IDs; low-BSP GOPs
contain fewer reusable frames. FM6 retains one substantive negative interval:
Figure~\ref{fig:gop-worst-trace} shows that it is not a Raw fallback or a
shifted boundary, but active masking that increases H.264 cost on several
frames. Unique-template count has only a weak association ($\rho=0.17$), so
template count alone is not an explanation. These are descriptive H.264 correlations,
not causal claims: scenecut placement is codec-dependent. A documented
FC5-only SVT-AV1 CRF42/GOP60 diagnostic has all ten fixed windows positive
($1.47$--$8.71\%$), but it is neither the same GOP definition nor a matched
15-clip suite. We therefore treat it as a consistency check, not evidence for
a cross-codec ordering; a codec-generality claim requires matched AV1 encodes.
\textcolor{red}{For SC, mask coverage, Rec activity, and reuse likewise accompany
positive GOP savings; even its lowest-saving GOP remains at $+3.44\%$.}

\subsection{Metadata, Templates, and Cache State}
\label{sec:res-netbw}

\parab{RMD is small.}
Measured RMD averages about 49~B/frame for FC5, 53~B/frame for FM6, and
205~B/frame for Mario. The per-clip table shows that RMD does not determine the
warm-cache ordering. Template assets are different: they are paid once and
can dominate short sessions.
\textcolor{red}{SC contributes 55~B/frame of measured RMD on average.}

\parab{Exact template accounting replaces the synthetic model.}
MSK1 already carries a stable numeric template ID. For learned-path runs we
join that ID to the saved latent-bank entry and charge the exact referenced
PNG file size; for pixel runs we charge the exact path carried by MSK1. We
rank the \emph{observed referenced IDs} by reuse, not randomly. Cold, 10\%,
25\%, 50\%, 75\%, and warm mean 0, 10, 25, 50, 75, and 100\% of that ranked
set resident before playback.

Table~\ref{tab:measured-cache} changes the conclusion of the former 8-KiB
synthetic sensitivity study. The saved learned templates are large PNG assets:
shipping them literally makes cold and partially warm FC5/FM6 sessions
strongly net-negative. Only a fully resident observed set recovers the warm
$+6.2\%$/$+14.1\%$ video-plus-RMD result. Mario's small pre-known pixel
library remains positive. This is a measured artifact-level result, not a
claim that a production system should ship unoptimized PNGs; it establishes
that template compression, deduplication, or predeployment is required.

\subsection{Summary and Limitations}
\label{sec:res-summary}

The primary warm-cache CRF23 result is positive for every evaluated clip, but
the gain is conditional. Rec coverage and reuse explain much of the H.264 GOP
ordering; short, mostly-Raw GOPs can be byte-negative. Fixed-VBV photoreal
streams remain byte-neutral. Exact template accounting shows that literal
on-demand transfer of the current learned PNG banks overwhelms short-session
savings, making predeployment or a compact template representation a
requirement rather than an optimization. Finally, the full FM6 processing path
misses 30 fps even though client compositing alone fits the budget.
\textcolor{red}{All 27 SC GOPs are positive, SC averages $+2.28\%$ under fixed
VBV, and its full measured processing path also misses 30 fps.}
\textcolor{purple}{At the nearest measured VMAF checkpoint, \sysname uses fewer
bytes than GRACE on each full representative clip; GRACE's loss-resilience
advantage remains orthogonal and is not measured by this zero-loss comparison.}

The evaluation remains limited to three titles, cropped FC5, one
desktop-class host, and no decode-only client baseline. The five FM6 entries
are equal partitions of four retained captures rather than five independent
captures, and the exclusion/repartition policy is post-hoc. H.264 GOP
correlations have not been replicated with AV1. Reported quality tables use a
fitted per-game uplift on RESPAWN means; Mario still lags the baseline on
VMAF/PSNR after that transform, so whether Mario remains a quality result
should be decided after a dedicated alignment, scaling, pixel-format, and
region-quality audit.
\textcolor{red}{SC extends the evaluation to a fourth title, but its
1280$\times$720@30.303-fps, heal-only multipart-class-0 protocol differs
from the FC5/FM6 regimes, so cross-title comparisons remain descriptive.}
\textcolor{purple}{The GRACE comparison covers one full clip per photoreal
title and only a subset of discrete released rate checkpoints. Its framed
payload is not an official wire format, checkpoint quality is only
approximately matched, and packet loss, latency, and playback stability are
not evaluated.}
